# NYC 推理检查点与 15–17 日收益核查（2026-09-15）

## 保存策略

NYC 训练只在 episode 结束保存。保留每个 episode 的 EV/AEV 配对模型，以及按总收益选出的 best 配对模型、单独的 best_ev/best_aev。训练中途的 best_loss/best_combined_loss 不再生成。每个 best 标签只保留最新获胜模型；各 episode 末模型全部保留。

为兼容现有 Test 的查找和载入接口，文件名仍是 full_state_episode_N.pth / best_full_state_episode_N.pth，但内容标记为 inference_v1。内容包含在线 critic、图编码器、mixer、actor、队列/需求预测器、需求修正头、必要的预测配置与 readiness 标志、部署 beta 所需的训练步数，以及方法/充电模式/配对身份。没有 replay、optimizer、target 网络、loss history、训练诊断或仿真历史，也不另写一份不完整的 network-only 文件。

保存直接构造推理状态，不调用 extra_checkpoint_state 或 replay.state_dict；使用临时文件及原子替换，成功后再淘汰旧 best。旧训练格式的加载仍保留。推理文件用于 Test，不用于恢复完整训练过程。当前进程的 replay 和训练规则不变，因此这解决保存阶段的 replay 序列化峰值，不等于解决常驻 replay 的所有 RAM 占用。

Test 默认 best-reward 继续使用同轮配对 EV/AEV；--checkpoint-selection latest 使用最后一轮配对模型。不能把独立 best_ev 和 best_aev 混成一对。NYC --evaluate-only 不训练或覆盖模型。--checkpoint-replay 保留兼容参数，但 NYC 新保存策略始终不包含 replay。

已有旧文件不自动批量删除。新增的每轮检查点及 best 模型均按上述规则生成。

- 9 组 Q/assignment 往返测试：三种 value-function 类 × r1/r3/macro。换随机初始化后加载推理文件，部署 Q 与 OR-Tools assignment 完全一致；训练步数导致的 beta 和预测器 readiness 一致。

## 实现上的解释与归因限制

1. 每个 episode 的 reset 前进到下一需求日期，并重置车辆。车辆初始化种子随日偏移，需求种子为 32 + cumulative_episode_index。网络跨 episode 继续训练。因此日期、初始状态、模型同时改变，不是固定场景的单因素学习曲线。
2. 当前 beta = beta_max * min(1, max(training_step,joint_training_step)/500)。每 10 个仿真步更新一次，一天约 288 次，故第二天学习修正影响逐步增强。它是可能造成策略变化的因素，不是已证实的单独根因。
3. 动态加价按当时分区排队需求 / 可用供给计算，并相对全区最大比率归一化。调度改变供给和积压，也会改变 final_value。基础 fare 相近不保证实际服务收入相近。
4. 最直接的观测是后两天拒单更多、完成率降低。macro 第二天完成量下降约 22.1%，系统收益下降约 28.7%；r3 分别约 15.2% 和 17.5%。这说明减少服务量是重要表现，但不能从这些汇总量识别所有因果贡献。
5. 本地没有这次服务器训练的模型文件和逐单加价、接客距离记录，不能据此断言学习已退化或某一天固有地更难。需要固定每轮模型，在相同日期/种子上关闭学习，对比至少 3 个 checkpoint × 3 个日期，报告收益、完成率、拒单、实际成交加价、接客距离与空驶里程。

## 是否启用 full_demand

当前 --full-demand 是 Yellow + 非拼车 HVFHV；仍保持 Manhattan 起终点筛选。它改变订单来源、分布和基础价格，并非仅倍增 Yellow 数量。

以 11.21 mph 计算全部 Yellow 行程的载客工作量：15/16/17 日分别约 19828/21735/22427 车时，占 3000×24 名义车时的 27.5%/30.2%/31.1%。该指标不含接客、充电、空驶、拒单和时空不可达，不能当成实测利用率，但提示 Yellow-only 的全天平均载客负荷偏低。高峰和局部区域仍可短缺。

建议保留现有 Yellow 基线，增加 full-demand 作为另一组需求压力实验；训练和 Test 使用同一需求口径和一致的 checkpoint 命名空间。没有核查实际 HVFHV 文件前不声称 full-demand 下总订单数或收益必然提升。本地尚无对应 HVFHV 月文件，本次没有下载或执行 full-demand 全日训练。
