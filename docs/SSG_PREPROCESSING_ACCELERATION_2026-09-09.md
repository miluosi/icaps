# 精确 SSG 预处理加速

后续的 [AEV、站点与 relocation 规模敏感性实验](SSG_SCALE_SENSITIVITY_2026-09-09.md) 单独检验哪些输入结构能让 SSG 获得端到端收益，未修改本文的历史测量结果。

## 原因与结果

SSG 的总时间等于「量化与验证 + 缩图 + 流图构建 + 后端求解与解码」。OR-Tools 已经很快，缩掉一些边所省下的求解时间，可能小于 Python 缩图和建图的额外成本。

改动前，本机 3000 车辆 / 15000 订单的一次分阶段测量中，完整图建图 0.851 秒、求解 0.108 秒；SSG 建图 0.915 秒、求解 0.095 秒。缩图多花约 64 毫秒，却只省约 13 毫秒求解时间。Profile 显示约 49 万次逐弧构建与 351 万次 list append；还为大量零流量候选边构建 Python 元数据对象并逐项解码。

本次保留 SSG 的全局最优目标，改造其预处理实现。下表是同一进程串行运行、相同 ADP 输入、种子 2101–2105、交替执行顺序的成对测量，单位秒，均为算术平均值；完整图也使用同样的公共构图优化。

| 车辆 / 订单 | 修改前 MCMF | 修改前 SSG+MCMF | 修改后 MCMF | 修改后 SSG+MCMF | SSG 自身加速 |
|---|---:|---:|---:|---:|---:|
| 1000 / 5000 | 0.092226 | 0.104188 | 0.049608 | 0.048644 | 2.14× |
| 3000 / 15000 | 0.874118 | 0.917778 | 0.451141 | 0.454859 | 2.02× |
| 5000 / 25000 | 3.347743 | 3.460606 | 1.456711 | 1.427452 | 2.42× |

SSG 流程明显加速，但不能据此保证 SSG 在每个实例上都快于完整图 MCMF。3000 车辆仍相差约 3.7 毫秒；5000 车辆成对记录也有明显波动。因此对两者小幅差异应判断为接近，不把平均值约 2% 的领先当成稳定优势。

随后用最终代码运行默认四种方法对照（每档五个相同 ADP 种子，共 100 次求解，全部最优目标一致），得到以下平均总时间：

| 车辆 / 订单 | CPLEX | MCMF | SSG+CPLEX | SSG+MCMF |
|---|---:|---:|---:|---:|
| 1000 / 5000 | 0.485877 | 0.049331 | 0.432201 | 0.050540 |
| 2000 / 10000 | 1.832779 | 0.208748 | 1.596012 | 0.209961 |
| 3000 / 15000 | 4.062297 | 0.499486 | 3.528613 | 0.502221 |

3000 车辆的最终四种方法对照中，SSG+MCMF 比 SSG+CPLEX 快约 7.03 倍；相对 MCMF 的差距约为 2.7 毫秒（0.55%）。这是独立于成对新旧版本实验的一次运行，不应混用两组耗时计算加速比。

## 改了什么

实现位于 `src/exact_mcmf.py`，现有计时脚本、训练入口和精确后端都会使用新的公共构图流程。

1. **分块量化。** 仍验证整张 Q 矩阵，包括不可行位置；逐块调用相同 `quantize_qvalues`，保留同样的整数网格、signed-zero 处理、舍入统计和溢出检查。稠密 Q 及整数结果仍独立持有；临时差值和中间量限制在约 262144 个元素的块内，减少大矩阵副本。
2. **批量容量证书。** 用可行边数组计数，折叠一批非紧约束动作，并按行批量选择严格改善的基线。正收益度数只初始化一次，随后扣除新支配的共享边。高于全局最大基线的边必然不被支配，可免去对应的逐行基线查询；这只是精确数值界，不是 top-K 或采样。
3. **深级联仍使用原算法。** 最多执行四轮批量折叠；仍有新证书时，用原有单调指针算法完成完整固定点。不会因为达到四轮就停止缩图，也不会引入按轮数增长的全图扫描复杂度。
4. **数组一次构图。** 用计数和偏移预分配 tails、heads、capacities、costs，不再对每条边维护多份 Python list 并创建 `ArcMeta` 对象。
5. **按需元数据与解码。** `ArcMetadata` 提供兼容的序列索引、迭代和切片，底层保存数组。解码只读取非零流量弧的元数据，仍用 Python 整数累加费用，并执行完整分配、可行性、容量与目标一致性验证。

## 为什么不改变全局最优

缩图仍使用原来的严格支配规则和容量证书：同一轮同时折叠；基线只有严格改善才替换；同一批最大收益的并列 witness 取最小动作编号。没有 outside action 的行继续进入共享容量约束核心，绝不虚构零收益等待。

不仅检查了最终 objective，还与修改前完整源码进行了 **1000 组结构对照**（500 个随机种子，各含完整图与 SSG）：

- 可行性矩阵、量化前后语义、容量数组相同；
- 基线动作、基线值、可用性、共享动作与逻辑缩图轮数相同；
- 保留的弧集合及其两端节点、容量、整数费用、原始费用、元数据全部相同；
- 舍入条目数、最大舍入差值、节点数、目标流量等诊断相同。

新实现按动作编号排列同一行的候选弧，旧 SSG 曾按 Q 值排序；边集合相同。最优值不变，但有多个等价最优分配时，求解器可以返回不同的最优分配。

最终 256 项相关测试已通过，包含直接求解器和 recourse/NYC 集成检查。新增检查包括九轮级联、与旧单调缩图逐项对照、分块边界、非连续矩阵、输入独立持有、不可行位置的 NaN/Inf、空图、整数边界和元数据序列接口。

## 复杂度与限制

令 N 为车辆数、A 为动作数、M 为可行车辆—动作边数、d_i 为每行可行度。

- 新增批量证书和数组建图为常数轮 `O(M+N+A)` 工作；极端级联交回单调算法，因此仍保留约 `O(NA + Σ d_i log d_i + M + A log A)` 的总体上界。
- 整个流程仍有稠密输入验证和两个稠密结果数组，时间与存储仍有 `O(NA)` 项。此次不是把整个系统声称为 `O(M)`。
- 当前 ADP 大规模图只缩减约 13% 的弧，原生 MCMF 的计算成本本来就低；缩图是否净省时取决于省下的后端工作能否覆盖精确证书成本。
- 不使用并行、GPU、降低 Q 精度或近似剪枝。评估对象是一次分配计算，不是完整训练/NYC 仿真的总时长。
